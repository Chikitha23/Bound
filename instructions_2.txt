Task 4.1: Implement Retry Logic

Algorithm:

Try to execute the function
If it succeeds, return the result
If it fails and retries remain:
Calculate backoff delay: delayMs * 2^(attempt - 1)
Add jitter (random 0-100ms) to prevent thundering herd
Wait for the calculated duration
Retry

Deliverable: Rate Limiter
File to complete: src/utils/rate-limiter.ts

The rate limiter prevents API throttling using a token bucket algorithm with sliding window.

Understanding the Sliding Window
The sliding window tracks requests made in the last 60 seconds:

At any moment, only count requests from the past 60 seconds
As time passes, old requests "fall off" the window
This provides smooth rate limiting vs. fixed time buckets

Troubleshooting
Rate limiter not preventing errors
Symptom: Still getting rate limit errors from API

Common Causes:

Rate limiter not integrated with orchestrator
acquire() not called before API requests
release() not called after requests complete
Limits set too high for your API tier
Solution: Integrate rate limiter by wrapping your orchestrator's query calls:

await rateLimiter.acquire(estimatedTokens);
try {
  const result = await orchestrator.reviewPullRequest(...);
  return result;
} finally {
  rateLimiter.release();
}
