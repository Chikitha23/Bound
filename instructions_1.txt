This guide walks you through building the core of your multi-agent code review system. By the end of Part 1, you'll have a minimal working system that can analyze a GitHub pull request using three specialized subagents.

What you'll build in Part 1:

MCP server configuration for GitHub and ESLint integration
Three specialized subagents with targeted prompts
Main orchestrator that coordinates subagents and aggregates results
What comes next in Part 2:

Production utilities (error handling, rate limiting)
Complete CLI application with validation
Comprehensive testing
Final deliverables (9 PR reports for submission)

Deliverable: Prompt Engineering
Create targeted prompts in src/prompts/ for each agent.

Prompt Engineering Principles
Effective prompts must:

Be specific about the task - What exactly should the agent analyze?
Reference the output format - How should findings be structured?
Provide evaluation criteria - What makes an issue "high severity"?
Give examples - Show what good vs. bad findings look like (optional but helpful)
Explain tool usage - When to invoke skills, what tools are available

Phase 3: The Orchestrator Logic
Deliverable: Main Orchestrator Implementation
The orchestrator coordinates all subagents and aggregates their findings into a structured report.

Task 3.1: Orchestrator Prompt
File to create: src/prompts/orchestrator.prompt.ts

This is the most critical prompt. It must instruct the main agent to:

Fetch PR data using GitHub MCP tools
Invoke all three subagents for analysis
Aggregate results into the ReviewReport schema
Key Concept - Explicit Invocation:

To reliably trigger subagents, your prompt should use explicit language like:

"Use the code-quality-analyzer agent to analyze src/file.ts"
NOT "The code-quality-analyzer should analyze..."
Questions to Answer:

Which MCP tool fetches pull request data? (Hint: Check GitHub MCP documentation)
Should subagents run in parallel or sequentially? Why?
How should the orchestrator handle if a subagent fails?
What should the final output structure look like? (Study ReviewReportSchema)
